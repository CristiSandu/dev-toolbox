01 / Using the feature

The screenshot workflow

  1. Paste, select, or dropOn Task Generator, paste an image from the clipboard, choose a PNG/JPEG, or drop one onto the import area.
  2. Wait for local recognitionProgress is shown while OCR reads the image. Cancel or retry if needed.
  3. Review the suggestionsCorrect the issue key and summary. Choose a candidate when several issue keys are found.
  4. Apply, then saveApply replaces the form fields. Save Task separately adds the reviewed task to history.
Normal text paste still works in form fields. Cancelling leaves the task form unchanged.

05 / Local operation

Bundled OCR, controlled resources

Privacy

  • Worker, WASM, and English model ship with the app.
  • No OCR service, CDN, or first-run model download.
  • Screenshots and raw OCR text stay out of task history and application logs.
  • Closing review releases the image URL and in-memory references.

Resource limits

  • PNG or JPEG, up to 10 MiB.
  • Up to 16 megapixels and 8192 pixels per side.
  • One recognition job at a time.
  • Cancel, route changes, or a two-minute timeout terminate the workers.

OCR assets add about 25 MiB before installer compression. The app’s separate update check still uses the network.

Asset preparation: predev / prebuild → public/ocr/ → packaged frontend

06 / Persistence

Jira type and Git type
have separate meanings

Jira issue typeSuggested Git branch type
Bugbugfix
Story, Task, Epic, Sub-taskfeature
Unknownfeature default; user can change it
Any issue typehotfix remains a manual choice

Existing database

A transaction adds nullable jira_issue_type and advances schema version 0 → 1. Existing rows and code history remain intact.

Task backups

Exports use version 1.1. Imports accept 1.0 and 1.1, validate Jira types, and insert atomically with fresh IDs.

Code-history backups keep version 1.0. Unknown future schema or task-backup versions are rejected.
